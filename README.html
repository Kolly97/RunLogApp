RunLog

Lokale Trainingsplanung & Analytics für Langstreckenläufer — offline, keine Cloud, keine Kompromisse.

Node.js ≥ 22 SQLite lokal Strava-Sync TrainingPeaks-Modell ⬇ Download

Voraussetzungen & Loslegen

Node.js ≥ 22 — nutzt das eingebaute node:sqlite, kein nativer Build nötig. Getestet mit Node 25.

Entwicklungsmodus

bashnpm install          # einmalig
npm run dev          # → http://localhost:5173

Produktivbetrieb (ein Prozess)

bashnpm run build && npm start   # → http://localhost:3000

Daten liegen in data/training.db (SQLite) — einfach sichern, liegt mit im iCloud-Ordner. Im Footer führt „Anleitung" zur Schritt-für-Schritt-Übersicht.

Seiten & Features

Dashboard

PMC (2fr) + Aktuelle Woche (1fr) nebeneinander. Darunter Saison-Progression + Intensity-Trend. Stat-Grid mit CTL/ATL/TSB/Ramp + VO2max-Kachel (VDOT, Niveau-Badge, Sparkline).

Wochenplanung

Einheiten je Tag mit km-je-Zone, Intervall-Builder, Drag & Drop. Live-Panel: geplante km, Zonenverteilung, TSS, projizierte Form, Ampel-Badge.

Tracking

Wochentag-Switcher (TSS-skalierte Punkte). Pro Tag: Wellness (Schlaf, HRV, Recovery, Strain, RPE…) und Aktivitäts-Kacheln mit % Plan-Erfüllung.

Wochenbericht

Geplant-vs-real-Tabelle mit Farb-Kacheln (≥90 % grün / ≥70 % gelb / rot), PMC, Efficiency Factor je Tag, Wellness-Schnitt, Reflexion → Drucken/PDF.

Langzeit

PMC + Saison-km, Intensity-Trend, Wellness-Verläufe (Schlaffenster-Chart, HRV, Recovery…), Zonen-Effizienz, Plan-Erfüllung, Intervall-Trend → druckbar.

Races

Wettkämpfe mit Endzeit, Distanz, Splits, Platzierung, HF, Höhenmeter, Notizen. Erscheinen als goldene Marker in allen Charts.

Bestzeiten

PBs je Standarddistanz aus Strava + Critical-Speed-Modell (CS-Pace, D′, R²) + Race-Prediction-Chart (5k/10k/HM/M über Saisonverlauf).

Methodik v1.6.0

N-of-1-Methoden-Engine: Marker-Batterie (CS primär, VDOT, Threshold, Entkopplung, EF…), geführte Vorher/Nachher-Experimente + passive Inferenz (welches Regime — polarisiert/pyramidal/threshold/Norwegian — bei dir mit Fortschritt korreliert; mit Confounder-Kontrolle).

Saisonplan

Wochen anlegen/bearbeiten, automatisch nach Datum sortiert und ab 0 nummeriert. Ziel-km direkt editierbar.

Profil

Athletenprofil (Geburtsjahr, Geschlecht, Max-HF), HF-Zonen Lauf + Fahrrad separat, Pace- und Power-Zonen. Profile umbenennen/löschen.

Einstellungen

Zonen-Sets mit Gültig-ab-Datum, Analyse-Schwellen, Strava-Verbindung.

Auswahllisten

Phasen, Sportarten, Einheitstypen, Tagesfaktoren — ohne Code-Änderung hinzufügen/umbenennen/umfärben.

Profile — mehrere Personen, ein PC

Der Profil-Wechsler oben in der Sidebar erlaubt mehrere unabhängige Nutzer (z. B. Kolja + Isabel). Jedes Profil hat eigene Saison, Einheiten, Tracking-Daten und Zonen-Sets — ohne Passwort, alles lokal.

Strava-Anbindung optional

Einmalig auf strava.com/settings/api eine kostenlose API-App anlegen — Callback-Domain: localhost.

Client-ID + Client-Secret in Einstellungen → Strava-Verbindung eintragen → „Mit Strava verbinden".

„Sync ab Datum" oder „Ganzes Jahr importieren" → PMC fürs ganze Jahr. Import holt km/Zeit/Ø-HF/Watt + Streams (NGP/NP, Zeit-in-Zone, Bestzeiten).

Datensicherheit: Strava-Sync überschreibt nie manuell bearbeitete Einheiten. Rate-Limit: 100/15 min + ~1.000/Tag — die App stoppt automatisch vor dem Tageslimit.

Auswertungs-Modell TrainingPeaks-angelehnt

TSS (geräteneutral)
Lauf = rTSS (NGP/Ø-Pace vs. Schwellen-Pace) · Rad = Power-TSS (NP/FTP) · Geplant per Zonen-Allokation. Manueller Wert hat Vorrang.
CTL — Fitness
42-Tage-EWMA der täglichen TSS.
ATL — Fatigue
7-Tage-EWMA der täglichen TSS.
TSB — Form
Gestrige CTL − gestrige ATL (TrainingPeaks-konform).
Intensity-Trend
ATL/CTL × 100 % · 5 Bänder (Decreasing → Excessive) · Optimal: 80–149 %.
VO2max
VDOT-Formel (Daniels-Gilbert) aus besten Laufzeiten · Niveau-Badge nach ACSM-Normen (Alter + Geschlecht).
Race-Prediction
Critical-Speed-Modell (CS-Pace + D′) → Prognose 5k/10k/HM/M über Saisonverlauf.
TSS-Empfehlung
3:1-Prinzip · Korridor aus CTL × Phase (Aufbau/Erhalt/Entlastung/Race Week/Krank) · Ampel-Badge in der Wochenplanung.
Periodisierung v1.6.0
Block-Vorschlag leitet Phasen vom Renntag ab (Base → Belastung → Race-Specific → Taper) + 3:1-Entlastung. Manuell gesetzte Phasen übersteuern immer.
Einheiten-Bibliothek v1.6.1
~23 sportwiss. Vorlagen (Daniels T/I/R · Norwegian/Bakken · Billat · Hügelläufe): je Phase rotierend + progressiv, fitness-skaliert (20×400 nur bei hoher Fitness), mit Pace-Bereich (Anker LT1/LT2/CS) + HF-Spanne + Pausen. Berg = Aufwand+HF.
Methoden-Findung (N-of-1) v1.6.0
Marker-Batterie (Critical Speed primär) → Vorher/Nachher-Verdikt + Konfidenz; passive Regime-Inferenz über 2–4-Wochen-Lag mit strenger Confounder-Kontrolle (CTL-Band; Krank/Taper/Race raus). Korrelation, nicht Kausalität — advisory, nie erzwingend.

Desktop-App v1.0.0

Fertige Installer in den GitHub Releases — ohne Terminal, mit Desktop-Icon:

🍎 macOS

Datei: RunLog-1.0.0-arm64.dmg

Herunterladen → öffnen → RunLog in Programme-Ordner ziehen.

⚠ Gatekeeper (App unsigniert): Meldung „… ist beschädigt" oder „Apple kann nicht auf Schadsoftware prüfen". Einmalig im Terminal das Quarantäne-Flag entfernen:
xattr -dr com.apple.quarantine /Applications/RunLog.app

Datenpfad: ~/Library/Application Support/RunLog

🪟 Windows

Datei: RunLog-Setup-1.0.0.exe

Installer ausführen → Pfad wählen → Startmenü-Eintrag wird angelegt.

⚠ SmartScreen: „Weitere Informationen → Trotzdem ausführen" (Installer unsigniert).

Datenpfad: %APPDATA%\RunLog

🐧 Linux / Ubuntu

.deb (Ubuntu/Debian):

sudo apt install ./RunLog-1.0.0-amd64.deb

.AppImage (portabel):

chmod +x RunLog-*.AppImage && ./RunLog-*.AppImage
Auf Ubuntu 24.04 ggf. sudo apt install libfuse2 nötig.

Datenpfad: ~/.config/RunLog

Daten weitergeben / zurücksetzen

Trainingsdaten liegen ausschließlich in data/training.db — gitignored, nie im Repo.

Update
data/-Ordner in die neue Version kopieren — fertig. Eine alte training.db im Wurzelordner wird einmalig automatisch übernommen.
Leere Vorlage
npm run db:template → schreibt training.empty.db (nur Schema, keine Daten).
Neu anfangen
npm run db:reset — sichert aktuelle DB automatisch und legt eine frische an.

Architektur

Backend — server/

  • db.ts — Schema, Migrationen, Profile
  • load.ts — TSS/PMC/NGP/Best-Efforts/Zonen-Splits
  • analysis.ts — Prüf-Engine, Plan-Erfüllung
  • zones.ts — Zonen-Sets nach Datum/Profil
  • strava.ts — OAuth, Sync, Zonen-Import
  • index.ts — Express-API + statisches Hosting

Frontend — client/

  • pages/ — Haupt-App-Seiten
  • charts/ — Recharts-basierte Charts
  • components/ — geteilte Komponenten
  • lib/api.ts — zentraler API-Client
  • lib/util.ts — Formatter & Helpers
  • lib/options.ts — Label & Farben
Migrationen sind strikt additiv — ALTER TABLE ADD COLUMN + v2-Tabellen mit Kopie. Bestandsdaten werden nie angetastet.
