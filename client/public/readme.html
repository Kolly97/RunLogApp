RunLog

Lokale Trainingsplanung und Analytics für Langstreckenläufer — im TrainingPeaks-Stil, komplett offline.

Was ist RunLog?

RunLog ist eine lokale Desktop-Web-App für wöchentliche Trainingsplanung, Tracking und sportwissenschaftliche Auswertung. Keine Cloud, keine Abos, keine fremden Server — alle Daten liegen in einer SQLite-Datenbank auf deinem Rechner.

Kern-Workflow: Woche planen → Einheiten tracken → Wochenbericht drucken → Langzeitentwicklung analysieren.

Seiten

  • Dashboard — PMC (CTL/ATL/TSB), Aktuelle Woche, Saison-Progression, Intensity-Trend, VO2max-Kachel.
  • Wochenplanung — Einheiten je Tag mit km/min/Zonen/Intervallen; TSS-Empfehlung, Drag & Copy.
  • Tracking — Wellness-Eingabe + Strava-Aktivitäten; Plan-Erfüllung je Einheit.
  • Wochenbericht — Druckfertiger A4-Bericht; Kacheln frei verschiebbar (WYSIWYG-Druck).
  • Langzeit — PMC, Wellness-Verläufe, Effizienz, Intervall-Trend; ebenfalls frei layoutbar.
  • Races — Wettkämpfe mit Splits, automatisch aus Tracking und Planung übernommen.
  • Bestzeiten — PBs aus Strava + manuell editierbar; Critical-Speed-Modell + Race-Prediction.
  • Saisonplan, Profil, Einstellungen, Auswahllisten — Konfiguration ohne Code.

Auswertungsmodell

rTSS = (Dauer_h) × (NGP / FTP)² × 100   — Lauf
Power-TSS = (Dauer_h) × (NP / FTP)² × 100   — Rad
CTL = 42-Tage-EWMA(TSS)   |   ATL = 7-Tage-EWMA(TSS)
TSB = CTLgestern − ATLgestern
  • VO2max — VDOT-Schätzung nach Daniels-Gilbert aus Bestzeiten (Rolling 90 d).
  • Race-Prediction — 2-Parameter-Critical-Speed-Modell (CS + D′) aus aeroben PBs.
  • Plan-Erfüllung — TSS-Treffer + Pace-Zonen-Overlap je Einheit.
  • Intensity-Trend — ATL/CTL × 100 % mit 5 COROS-Belastungsbändern.

Technischer Stack

Node.js ≥ 22 Express SQLite (node:sqlite) Vite + React TypeScript Recharts react-grid-layout

Starten

npm install (einmalig), dann npm run dev → localhost:5173
Für den Alltag: npm run build && npm start → localhost:3000

Daten

Liegen in data/training.db (gitignored). Beim Update einfach den data/-Ordner kopieren. Migrationen sind immer additiv — keine Bestandsdaten gehen verloren.
